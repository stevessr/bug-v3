# Extension permissions

This page explains every permission declared by `public/manifest.json` and why the extension requests it. Required permissions are granted by the browser when the extension is installed or updated. `cookies` is optional and is requested at runtime only when a user starts a feature that needs cookies for a specific site. Permission availability and prompts can vary by browser.

## Required permissions

| Permission        | Why it is needed                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `storage`         | Save emoji groups, favorites, settings, caches, and synchronization/workflow state in the browser's extension storage, and synchronize changes between extension pages, the background worker, and content scripts.                                                                                                                                                                                                                              |
| `activeTab`       | Temporarily access the tab the user explicitly invokes the extension on, for actions such as opening the picker or inserting an emoji. This is narrower than persistent access to every site; the extension also declares host access below for its always-available page integration.                                                                                                                                                           |
| `scripting`       | Inject or execute the extension's content functionality in a tab when a user-requested action or supported site workflow requires it.                                                                                                                                                                                                                                                                                                            |
| `downloads`       | Start and manage downloads explicitly requested by the user, including exported data and downloaded emoji images.                                                                                                                                                                                                                                                                                                                                |
| `sidePanel`       | Open and configure the extension's emoji and management interface in the browser side panel.                                                                                                                                                                                                                                                                                                                                                     |
| `tabs`            | Find and communicate with relevant tabs, open extension or OAuth pages, update/navigate tabs for user-requested Agent actions, and coordinate page integrations and workflows. The extension does not use this permission to collect browsing history.                                                                                                                                                                                           |
| `tabGroups`       | Read or update tab-group information when the user invokes Agent/MCP tab-group actions.                                                                                                                                                                                                                                                                                                                                                          |
| `alarms`          | Schedule and resume user-configured background workflows and periodic maintenance reliably, including when the service worker is suspended.                                                                                                                                                                                                                                                                                                      |
| `downloads.shelf` | Temporarily hide and restore the browser download shelf while an extension-managed image download is initiated, where supported by the browser.                                                                                                                                                                                                                                                                                                  |
| `downloads.ui`    | Temporarily configure the browser's download UI during an extension-managed image download, where supported. This is used as the preferred API when available; `downloads.shelf` is the compatibility fallback.                                                                                                                                                                                                                                  |
| `notifications`   | Show user-visible results or status for configured background workflows, synchronization, and site-specific helper actions.                                                                                                                                                                                                                                                                                                                      |
| `identity`        | Run OAuth authorization flows for user-configured MCP/connected services using the browser's identity redirect handling. It is not used to identify users for analytics.                                                                                                                                                                                                                                                                         |
| `debugger`        | Chromium-only permission used by the Agent's optional Developer Observation feature to attach to a tab and inspect console/network diagnostics after the user enables that feature and starts a debug action. The permission is declared as required because Chromium does not support requesting `debugger` as an optional permission. Merely installing the extension does not start debugging. Firefox builds do not request this permission. |

## Optional permission

| Permission | When it is requested and why                                                                                                                                                                                                                                                                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cookies`  | Requested for the origin involved only when the user starts a feature that needs an authenticated site session, such as a logged-in Linux.do/Discourse operation or a configured cookie-bearing proxy request. The cookie is used to make that user-requested request to the site; it is not sent to the extension maintainer. The user can deny or revoke this optional access. |

## Host access

Host access is separate from the named API permissions above. It lets page integration work on sites the user visits; content scripts are also configured to match all URLs.

| Host pattern | Why it is needed                                                                                                                                                                                                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<all_urls>` | Make the emoji picker and insertion integration available across websites, and allow user-invoked site workflows to interact with the selected page. Site access remains subject to browser restrictions (for example, browser-internal pages may not allow extension injection). |
| `file:///*`  | Allow the same picker/insertion integration on local files when the user enables the browser's separate “allow access to file URLs” setting for the extension. This does not grant access to local files by itself.                                                               |

The extension uses page and optional site access to provide its features, not for telemetry or advertising. See [PRIVACY.md](./PRIVACY.md) for the privacy policy.
