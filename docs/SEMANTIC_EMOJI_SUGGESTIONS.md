# 表情包语义联想（实验性）

此功能通过用户自行配置的 **文本 Embedding 深度学习模型**，把用户在表情选择器中输入的查询和表情名称/标签/分组描述转换成向量，再通过归一化余弦相似度、精确关键词加权和轻量使用频率加权输出候选。该方案参考微信/QQ 的输入联想交互，但**不是微信或 QQ 的模型或算法复刻**，目前只对有描述文字的收藏表情进行检索，并不对图片进行视觉识别。

## 开启方法

在扩展 **设置 → AI → 表情包语义联想（实验性）** 启用，然后填写独立的、OpenAI-compatible `/v1/embeddings` 接口。示例：API Base URL 为 `https://api.openai.com/v1`、模型为 `text-embedding-3-small`，并提供相应的 API Key；也允许 `http://localhost` / `http://127.0.0.1` 的本机服务（可不填 Key）。注意：**这里配置的是文本 Embedding 模型，不是聊天生成模型，也不继承现有 Gemini/聊天模型的 API Key。** 建议先在服务提供方确认模型支持 `input: string[]` 和带 `index` 的向量返回格式。

在扩展弹窗搜索栏，或 Discourse 注入的桌面/移动版表情选择器搜索栏，输入至少两个字符，例如 `好累`、`笑死`、`开摆`。原有关键词结果立即显示；输入停止 500 ms 后异步请求语义结果。弹窗会把相关表情排在原有结果之前，Discourse 选择器会新增横向 AI 联想候选栏；失败时保留原有名称关键词搜索。

## 隐私和资源

- 默认关闭。只有手动开启且**主动输入表情搜索框**时才调用模型；不会监听聊天输入框、发送按键、聊天历史、私信或页面正文。
- 每次向配置的提供商发送当前搜索关键词，以及最多 1000 个候选的**名称、标签和分组名文本**。不发送图片像素、URL、帖子内容或网页凭据。API Key 仅通过扩展后台发往配置的提供商；请自行核对提供方政策、费用和项目已有的设置同步行为。
- 第一次使用时，最多 1000 个候选元数据会分 64 条的批次计算向量，通常比后续查询慢，也可能产生 API 费用。元数据向量仅缓存在当前扩展后台的内存中（上限 1200 项）；后台休眠/重启则需要重新生成。**搜索关键词不进入缓存。**
- 要求 HTTPS；本机 localhost HTTP 例外。使用 15 秒/批次超时，响应校验向量与条目索引，旧输入的异步结果不会覆盖新查询。提供方异常不应影响原始搜索和点击插入流程。
- 无图像模型：如果表情图片的名称是 `123.jpg` 且没有标签，目前无法仅凭其图片内容正确联想；可先用项目现有 AI 命名/标签管理为图片生成描述，再使用语义搜索。

## 验证

依赖管理使用仓库规定的 `pnpm`：

```bash
pnpm install --frozen-lockfile
pnpm type-check
pnpm build
pnpm exec playwright test scripts/tests/semantic-emoji-suggestions.spec.ts
```

端到端实际模型调用需用户配置自己的兼容 Embedding 提供商。可进一步增加 mock API 测试，模拟慢响应、断网、错误向量维度、空库和超过 1000 条数据的情况。
